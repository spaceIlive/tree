LLM 대화의 컨텍스트를 그래프로 관리하는 학습 도구

← → 방향키로 이동

문제

대화가 누적될수록, 주제가 뒤섞인다

대화형 AI를 통해 학습하는 사람은, LLM과의 대화가 누적되면서 다양한 주제가 혼재되어,
LLM에게서 원하는 대답을 얻기 힘들다.

실제로 일어나는 일

A논문 설명해줘
attention 메커니즘 기반으로... encoder-decoder 구조... positional encoding으로 순서 정보...
attention이 뭐야?
... Q,K,V ... softmax ...
softmax는 왜 씀?
... 수치 안정성 문제로 log-sum-exp...
다시 논문 얘기로 돌아가서, 실험 결과는 어때?
(곁가지 대화가 맥락에 뒤섞인 채로 답변 → 원하는 초점을 잃음)

고통의 정체

  • 컨텍스트 오염 — 곁가지로 팠던 대화가 맥락에 뒤섞여 이후 답변의 초점을 흐림
  • 컨텍스트를 골라 넣을 수 없음 — 지난 대화 중 필요한 부분만 모델에게 주고 싶어도 방법이 없음. 결국 새 창을 열고 처음부터 다시 설명
  • 모델이 뭘 보고 답하는지 알 수 없음 — 질문을 보내면 지난 대화 중 무엇이 함께 전달되는지 화면 어디에도 표시되지 않음
  • 비용·품질 저하 — 대화가 길어질수록 토큰은 늘고 답변 품질은 떨어짐
뒤섞인 주제를 갈래로 분리하고 — 컨텍스트를 보이게, 고를 수 있게 만들어야 한다.
해결 구조

노드 = 질문·답변 한 쌍, 경로 = 컨텍스트

대화를 Q&A 한 쌍 단위의 노드로 쪼개고, 선택한 노드에서 루트까지 엣지로 이어진 경로만 컨텍스트로 넣는다.
경로 밖 대화는 컨텍스트에 들어가지 않는다 — 오염 원천 차단.

사용자가 마지막 노드를 지정했어도

분기 엔진는 선택한 노드가 속한 트리의 모든 노드를 순회하며 "이 질문은 어느 노드 아래가 맞는가"를 먼저 판단한다. 사용자의 선택은 존중하되, 더 나은 위치가 있으면 근거와 함께 제안한다.

LLM에 들어가는 것은 딱 세 가지

위치가 확정되면 ① 그 노드에서 루트까지 경로의 Q&A ② 노드에 주입된 컨텍스트 ③ 새 질문으로 인풋을 조립해 LLM을 호출한다. 형제·다른 서브트리의 대화는 절대 섞이지 않는다.

이유: A논문(루트) 노드의 텍스트와 가장 유사 — softmax 경로와는 무관한 갈래
[A논문 아래에 새 노드 만들기] [그냥 여기서 답변]

승인하면 A논문 아래 "encoder-decoder" 노드가 생기고, 컨텍스트도 그 경로(A논문→encoder-decoder)로 깨끗하게 잡힌다. 트리 안 어디서 물어봐도 분기 엔진가 위치를 잡아주므로, 사용자는 고민할 필요가 없다.

핵심 순간 ② — 트리를 넘나드는 비교 · STEP 1/3 (인터랙티브)

시작: 트리 두 개, 그리고 빈 노드 하나

A논문(Transformer) 트리와 B논문(Mamba) 트리를 각각 공부해 둔 상태. 두 트리를 비교하고 싶어진 사용자가 ＋ 새 노드로 빈 노드 "개념 비교"를 만들었다 — 아직 컨텍스트는 비어 있다.

Path:
Context Map
＋/더블클릭 = 새 노드 · 클릭 = 전환
트리가 여러 개 공존할 수 있다 — 트리끼리는 컨텍스트가 완전히 분리됨
양쪽 트리의 노드를 클릭해 보면 각자의 경로만 보이는 걸 확인 가능

다음 단계: 두 트리에서 필요한 개념 노드만 드래그 박스로 선택해 새 노드에 드롭한다.

핵심 순간 ② — 트리를 넘나드는 비교 · STEP 2/3

중간: 두 노드를 떨어뜨리자, 시스템이 묻는다

사용자가 맵에서 드래그 박스로 attention과 selective scan을 함께 선택해 "개념 비교" 노드 위에 놓았다. 놓는 순간 시스템이 어떻게 넣을지 묻는다. (⌘C → ⌘V로 텍스트·코드를 직접 넣는 것도 가능)

Node: 개념 비교 — 드롭 직후
🔗 드래그로 선택한 2개 노드(attention · selective scan)를 놓았어요. 어떻게 넣을까요?
[이 노드들만 (기본)]  [루트까지 경로 포함]
이 노드들만 = 두 노드의 Q&A만 · 경로 포함 = A논문→attention, B논문→selective scan 두 경로 전체
사용자가 고민 중... 논문 배경까지 필요한 비교라서 →
✓ 사용자가 "루트까지 경로 포함" 선택
💬 아직 질문 전 — 컨텍스트 구성만 확정된 상태
Context Map
드래그 박스 = 다중 선택 · 끌어다 놓기 = 주입
선택된 두 노드(밝게)가 새 노드로 ┈┈ 점선(주입 참조)으로 연결됨 — 트리 엣지가 아니라서 두 트리 구조는 그대로

주입 방식은 넣는 순간 사용자가 선택 — 기본값은 "이 노드들만". 그리고 주입은 항상 스냅샷 — 이후 원본 노드가 바뀌거나 삭제돼도 여기 넣은 내용은 그대로다.

핵심 순간 ② — 트리를 넘나드는 비교 · STEP 3/3

결과: 이름이 달라도, 같은 일을 하는 개념이 비교된다

주입된 두 경로만 컨텍스트로 들어간 상태에서 질문 — LLM은 두 트리에서 쌓은 이해를 바탕으로 이름은 다르지만 역할이 같은 개념을 비교해 준다.

Node: 개념 비교 📎×2
✓ 2개 경로 주입됨 — A논문→attention · B논문→selective scan
attention이랑 selective scan, 이름은 완전 다른데 둘 다 "과거 정보 중 뭘 참조할지 고르는" 역할 아니야? 비교해줘
맞아요, 이름만 다르지 같은 문제를 푸는 장치예요.

공통점: 둘 다 입력 내용에 따라 "어떤 과거 정보를 얼마나 반영할지"를 동적으로 결정합니다.
차이: attention은 모든 토큰 쌍의 관련도를 매번 계산(O(n²))하고, selective scan은 게이트로 과거를 하나의 상태에 압축해 갑니다(O(n)). 주입해주신 두 논문 맥락으로 보면, B논문 자체가 A논문의 긴 시퀀스 비용 문제를 겨냥해 나온 후속 접근이에요...
💬 컨텍스트: 두 경로(A논문→attention · B논문→selective scan)만 — 다른 곁가지는 안 들어감
Context Map
＋/더블클릭 = 새 노드 · 끌어다 놓기 = 주입
새 노드 "개념 비교"는 어느 트리에도 속하지 않는 독립 노드 — 경로 포함이라 두 루트까지 밝게 표시
🔗 A논문→attention (경로 포함) 🔗 B논문→selective scan (경로 포함)

기존 채팅에서는 불가능했던 동작 — 세션 두 개를 열어 복붙하는 대신, 쌓아둔 대화의 조각을 골라 합친다. 곁가지(softmax·SSM 상태)는 어느 쪽이든 안 들어간다.

핵심 순간 ③ — 노드 삭제 · STEP 1/3

시작: 중간 노드를 지우려 하자, 시스템이 묻는다

사용자가 attention을 우클릭 → 삭제. 리프 노드면 그냥 지워지지만, attention은 자식 2개(softmax · multi-head)를 가진 중간 노드라 시스템이 처리 방식을 묻는다.

Path: 📄 A논문 › attention (삭제 요청됨)
📄 A논문 (루트)
A논문 설명해줘 📎
attention 메커니즘 기반으로 encoder-decoder 구조를 제안하며...
attention ← 삭제 대상
attention이 뭐야?
각 토큰이 다른 토큰을 얼마나 참조할지 가중치를 계산하는 메커니즘이에요...
🗑 attention은 자식 2개(softmax · multi-head)를 가진 중간 노드예요. 어떻게 삭제할까요?
[서브트리째 삭제 — 아래 전부 제거]  [자식은 부모에 이어붙이기]
이어붙이기를 고르면 추가 선택: 삭제된 노드의 한 줄 요약을 자식 경로에 [남기기 / 남기지 않기]
💬 선택 대기 중 — 다음 두 페이지가 각 선택의 결과
Context Map
우클릭 = 삭제
빨간 노드 = 삭제 대상 — 그 아래 softmax → log-sum-exp, multi-head 서브트리가 걸려 있음
루트를 지우면 자식들이 각각 새 트리의 루트가 됨
숨기기(soft delete)는 제공 안 함 — "보이는 것 = 모델이 아는 것" 원칙 위배

주입·삭제 모두 같은 패턴 — 구조가 바뀌는 순간, 사용자가 선택한다.

핵심 순간 ③ — 노드 삭제 · STEP 2/3 — 결과 ①: 서브트리째 (인터랙티브)

결과 ①: 통째로 지운다 — 다른 경로는 영향 없음

[서브트리째 삭제]를 고른 경우 — attention과 그 아래 전부(softmax · multi-head · log-sum-exp)가 함께 사라진다.

Path:
Context Map
클릭 = 전환 · 우클릭 = 삭제
빨간 점선 = 방금 삭제된 서브트리 (표시용 잔상)
남은 트리는 그대로 — 노드를 클릭하면 왼쪽 대화가 그 경로로 바뀝니다

경로가 서로 독립적이라, 곁가지 하나를 통째로 정리해도 다른 서브트리의 대화·컨텍스트는 전혀 변하지 않는다.

핵심 순간 ③ — 노드 삭제 · STEP 3/3 — 결과 ②: 이어붙이기 (인터랙티브)

결과 ②: 자식은 살리고, 요약 스텁으로 구멍을 메운다

[이어붙이기 + 요약 남기기]를 고른 경우 — 자식(softmax · multi-head)이 A논문 바로 아래로 올라간다. 하위 대화는 attention이 경로에 있던 시절에 만들어진 것이라 그냥 지우면 맥락에 구멍이 남는데, 삭제된 노드의 한 줄 요약 스텁이 그 자리를 메운다.

Path:
Context Map
클릭 = 전환 · 우클릭 = 삭제
softmax·multi-head가 A논문 바로 아래로 승계 — softmax나 log-sum-exp를 클릭하면 경로에 요약 스텁이 끼는 게 보입니다
숨기기(soft delete)는 제공 안 함 — "보이는 것 = 모델이 아는 것" 원칙 위배

스텁도 채팅창에 그대로 보인다 — 모델이 받는 컨텍스트와 화면이 어긋나지 않는다 (WYSIWYG 유지). "남기지 않기"를 고르면 스텁 없이 A논문 → softmax로 바로 이어진다.

핵심 순간 ④ — 리패런팅 · STEP 1/2 (인터랙티브)

시작: 위치가 잘못 잡힌 노드가 보인다

positional enc.가 A논문 바로 아래에 있다. 그런데 사용자가 보니 이건 encoder-decoder를 파다 나온 개념 — 지금 경로(A논문 › positional enc.)에는 encoder-decoder의 맥락이 빠져 있다.

Path:
Context Map
클릭 = 전환 · 노드 위로 드롭 = 리패런팅
현재 positional enc.는 루트 직속 — positional enc. 클릭하면 경로가 A논문 › positional enc. 2개뿐인 게 보입니다

사용자가 positional enc.를 집어 encoder-decoder 위로 드래그한다 → 다음 페이지가 결과.

핵심 순간 ④ — 리패런팅 · STEP 2/2 — 결과 (인터랙티브)

결과: 떼어서 다른 노드 아래에 붙었다

encoder-decoder 위에 드롭 → 그 자식으로 이동 완료. 옮기는 순간 positional enc.의 경로 컨텍스트가 새 위치 기준으로 즉시 재구성된다.

Path:

positional enc.를 클릭하면 경로가 A논문 › encoder-decoder › positional enc.로 잡히는 게 보입니다

이동 후 positional enc.에서 질문하면 encoder-decoder의 맥락이 새로 포함되어 들어간다 — 분기 엔진가 잘못 잡은 위치도 사용자가 언제든 바로잡을 수 있다.

핵심 순간 ⑤ — 끼워넣기 · STEP 1/2 (인터랙티브)

시작: 경로에 있어야 할 중간 개념이 딴 갈래에 있다

scaled dot-product가 A논문 직속의 별도 갈래로 잡혀 있다. 그런데 softmax는 사실 scaled dot-product 계산의 일부 — 지금 softmax 경로(A논문 › attention › softmax)에는 그 중간 맥락이 빠져 있다.

scaled dot-product가 루트 직속의 별도 갈래에 있음 — softmax를 클릭하면 경로에 그게 없는 걸 확인 가능

사용자가 scaled dot-product를 집어 attention–softmax 엣지 위로 드래그한다 → 다음 페이지가 결과.

핵심 순간 ⑤ — 끼워넣기 · STEP 2/2 — 결과 (인터랙티브)

결과: 부모-자식 사이에 끼워넣어졌다

attention–softmax 엣지 위에 드롭 → 두 노드 사이에 끼워넣기 완료. softmax 이하의 경로 컨텍스트에 빠져 있던 중간 맥락이 채워진다.

Path:
Context Map
클릭 = 전환 · 엣지 위로 드롭 = 끼워넣기
회색 점선 화살표 ┈▸ = 이동 경로 — 점선 칩(이전 위치)에서 attention–softmax 사이 자리로
softmax나 log-sum-exp를 클릭하면 끼워넣은 노드가 경로에 포함된 게 보입니다

삭제(케이스 B)의 요약 스텁이 경로의 구멍을 메우는 수단이라면, 끼워넣기는 빠져 있던 중간 맥락을 경로에 채워 넣는 수단 — 서로 반대 방향의 재구성.

제공 가치

왜 사용자가 이걸 쓰는가

Before

  • 모든 대화가 통째로 컨텍스트에 누적
  • 곁가지가 이후 답변을 오염
  • 모델이 뭘 알고 있는지 안 보임
  • 맥락 바꾸려면 새 창 + 처음부터 재설명

After

  • 경로 = 컨텍스트, 경로 밖은 안 들어감
  • 분기 엔진가 질문마다 최적 위치를 잡아줌
  • 화면에 보이는 대화 = 모델이 아는 것
  • 드래그·붙여넣기로 원하는 것만 주입
핵심 인사이트: LLM 시대의 UI 병목은 "생성"이 아니라 "컨텍스트 관리"다.
우리는 컨텍스트를 보이게 하고, 고를 수 있게 만든다.

나중에 고려할 것들

  • 트리 → 그래프 일반화 — 한 노드가 부모를 여러 개 갖는 구조. 경로 비교가 폭증하므로 K-V 캐시 재사용 등 비용 최적화 필요
  • 하위 종합 질문 — 중간 노드에서 그 아래 서브트리 내용까지 걸치는 질문을 하면, 경로(위쪽)만으로는 컨텍스트가 부족. 분기 엔진가 관련 하위 노드들을 감지해 주입 컨텍스트로 제안하는 방식 검토
  • 노드 병합 — 노드는 항상 Q&A 한 쌍. 트리가 커지면 여러 쌍을 요약해 하나의 노드로 합치는 기능으로 밀도 관리
  • 서브트리 접기 — 완료한 갈래는 접어서 맵을 가볍게. 접힌 것과 펼쳐진 것이 한눈에 구분되는 표시가 관건
